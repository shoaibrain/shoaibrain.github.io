About

I'm a software engineer based in Dallas, TX. Most of my work lives in the backend and infrastructure of multi-tenant SaaS — designing services, data models, and the AWS around them — with enough frontend to ship a product end to end.

I like problems where the domain is genuinely complex and the engineering has to stay simple anyway. I reach for boring, reliable tools, keep abstractions honest, and let tests and types do the guarding so the interesting parts stay easy to change.

Now

What I'm building at the moment.

EdForge

A better education information system for schools around the globe.

EdForge is a multi-tenant education management system — the operating system for a school, covering enrolment, academics, exams, results, and finance, plus the national reporting that ties a school back to its education data standard. It's designed around archetypes of school operations rather than a single country or district, so one codebase can serve very different schools.

I work across the stack: NestJS microservices on AWS ECS/Fargate, a single-table DynamoDB design per service, Cognito + attribute-based access control for tenant isolation, and an EventBridge-driven event flow — all provisioned with AWS CDK. The tenant-facing frontend is a React micro-frontend built with Module Federation.

How I work

  • Match scope to the problem. Three similar lines beat a premature abstraction; I add structure when the second or third real case earns it.
  • Types and tests as guardrails. Not an afterthought — they're what makes the interesting code safe to change later.
  • Small, reviewable commits. Clear history over clever history; the diff should tell the story.
  • Build for the real constraints. Actual users, actual data, actual failure modes — design for what production will do, not the happy path.
